## Durable storage and recovery

The existing schema-v1 personal SQLite owner remains authoritative; additive `hiking_version:1` metadata describes an app-owned catalog with recorded/recommended/manual/peak/visit kinds and stable relationships. A `hiking_assets` table stores exact immutable original blobs under SHA-256, separate from metadata. Normalized full-resolution points and derived cumulative distance are recreated from verified originals on demand, avoiding an extra durable point-array copy. Originals and metadata publish in the same guarded SQLite transaction with the existing document comparison and single owner, so interruption cannot expose a metadata reference without its original. Reversible archive retains originals; no physical source eviction is implemented.

Track limits: 16 MiB/file, 200,000 total GPX point elements, 128 tracks, 1,024 segments, 32 levels, 64 attributes/element and 4,096-byte scalar/text limits. Asset admission caps original blob bytes at 128 MiB. The display cache admits at most 64 sources and 32 MiB of original/normalized payload, with priority for selected sources. These payload caps do not bound total process RSS or SQLite/temp/backup file size. Version/type, original-byte identity, invalid coordinates, malformed XML/UTF-8/NUL, DTD/entities, unsafe file types and resource-limit failures refuse import. Invalid optional elevation/time values remain unavailable and appear in preview metrics alongside time-reversal/large-step warnings. Route-only GPX is refused as track geometry; route points/waypoints inside accepted files remain in exact originals and are reported separately.

Preview/commit binds source hash, request identity, current document token and edit revision. Repeated committed input returns its receipt; changed input reusing an ID refuses. A changed source with an existing external identity requires an explicit ID/revision update. Agent writes are blocked while a native history form or existing client draft is open. Native forms also retain their opening revision. Unsupported hiking catalogs are preserved rather than rewritten.

`repository.backup` creates a private complete SQLite snapshot including all GPX blobs. Backup/restore validates source bytes and hashes as well as SQLite integrity and metadata, refuses corrupt referenced assets, and makes a recovery snapshot before a guarded restore. The actual post-S7 snapshot was restored into a fresh disposable namespace: all 40 history records, all 32 originals and all client records matched, and Kaleetan's original export matched its download. `repository.export` is metadata-only JSON and explicitly reports `assets_included:false`; it is not a complete hiking backup. `history.export` writes the exact original create-only with private permissions. Existing export destinations are never overwritten.

## Native use and agent commands

Open Hiking & History. Click the filter label to cycle All/Recordings/Completed/Peaks/Visits; scroll the list and use Ctrl+F for name/date/area/source/state text. Select an entry, Fit selected, or Fit collection. The map reserves sidebar space so fitted western routes cannot disappear beneath the pane. Blue continuous lines are recorded sources; gold dashed lines are recommended paths. Segment boundaries are never connected, and history remains visible independently of street-map coverage. The footer reports an outside-region view explicitly. Original sources retain full resolution; map display omits points within a 2-pixel screen radius of the drawing anchor and culls offscreen lines, with a 6,000-line overlay ceiling. Selected point inspection and original export retain all source points. Elevation profiles use segmented cumulative distance with missing-elevation gaps and bounded screen sampling.

Add / Import opens a file/name/date/notes form; dropping GPX opens it. Preview is required before Import / Save. Peak latitude/longitude apply to peak entries; a visit can be entered with an existing peak selected. State controls require an explicit choice; unknown remains unreviewed. Edit details, Archive / Restore and Export GPX share the owner/revision contract. Escape cancels without changing records. Selection/workspace survives restart. Source details, point coordinates, optional elevation/time and provenance remain visible in the inspector. Broad terrain/hillshade is a subsequent S8 feature; a mountain route beyond current coverage is currently shown against the plain map background.

Structured CLI operations through the existing `mapforge_places --request <JSON>` surface:

- `history.list/get/point/export`: bounded catalog reads, exact source-point inspection and original export.
- `history.preview/commit`: recorded/recommended imports, manual history, peak/visit creation, metadata/link updates and reversible archive/restore.
- `history.nearby`: at most 128 active peaks and a 10–2,000 m radius; returns nearest source-point distances as suggestions with `confirmation_required:true`. No visit is created.

Track mutation input declares `kind`, `request_id`, absolute `source_path`, name and optional external identity/source/date/evidence. Commit adds preview's `candidate_token` and `expected_store_token`. Updates add `record_id` and `expected_revision`. Relationships use `peak_id`, `recording_id` and `trail_id`; the referenced kind must match. A source path is an intake input and is not retained in public/repository metadata. Native imports use C/libxml2 and the system SHA implementation; Linux tooling uses libxml2/OpenSSL. There is no automatic AllTrails personal sync claim.
